# Live VIDEO'ni yoqish — server (VPS) runbook

**Holat (2026-08-06):** Snapshot-live ishlayapti (agent → server, Live sahifada kadr).
Video uchun serverda MediaMTX ko'tarilishi kerak — **local agent tayyor**, server
configida `push_url` paydo bo'lishi bilan avtomatik video push'ga o'tadi (≤60s).
Tekshirildi: 69.62.127.130 da 8554/8888/8889 portlar hozir yopiq (MediaMTX o'chiq,
compose `profiles: ["live"]`).

Kechikish: HLS lowLatency ≈ 2–6 soniya — "biroz orqada bo'lsa ham live" talabiga mos.

---

## 1. Kuchli parol tanlang

Bitta parol IKKI joyda bir xil bo'ladi (masalan `openssl rand -hex 16` bilan):
- `mediamtx.yml` → `publishPass`
- backend `.env` → `MEDIAMTX_PUBLISH_PASS`

## 2. VPS'da `backend/mediamtx.yml`

`CHANGE_ME_STRONG_PASSWORD` → tanlangan parol.

## 3. VPS'da backend `.env`ga qo'shish

```env
MEDIAMTX_RTSP_URL=rtsp://api.raqamli-karyer.uz:8554
MEDIAMTX_PUBLISH_USER=agent
MEDIAMTX_PUBLISH_PASS=<tanlangan-parol>
MEDIAMTX_HLS_URL=https://api.raqamli-karyer.uz/live/hls
MEDIAMTX_WEBRTC_URL=https://api.raqamli-karyer.uz/live/webrtc
```

(`services/live.py` shu 5 sozlamani o'qiydi — `core/config.py:56-60`.)

## 4. Nginx (VPS'da, qo'lda boshqariladigan config)

HLS/WebRTC 127.0.0.1'ga bog'langan — nginx HTTPS ostida uzatadi:

```nginx
# api.raqamli-karyer.uz server bloki ichiga:
location /live/hls/ {
    proxy_pass http://127.0.0.1:8888/;
    proxy_http_version 1.1;
    # HLS segmentlari uchun kesh shart emas; CORS saytdan kelganda kerak bo'lsa:
    add_header Access-Control-Allow-Origin *;
}
location /live/webrtc/ {
    proxy_pass http://127.0.0.1:8889/;
    proxy_http_version 1.1;
    add_header Access-Control-Allow-Origin *;
}
```

`nginx -t && systemctl reload nginx`

## 5. Firewall: 8554/tcp ochish

Agent RTSP push shu portga keladi (parol bilan himoyalangan):
```bash
ufw allow 8554/tcp    # yoki hosting panelidagi firewall'da
```

## 6. Ishga tushirish

```bash
cd <repo>/backend
docker compose -f docker-compose.prod.yml --profile live up -d mediamtx
docker compose -f docker-compose.prod.yml up -d backend   # yangi env o'qilsin
```

## 7. Adminkada sifatni tanlash

Karyer sahifasi → Agent → `video_quality` = **`low`** qiling (birinchi sinov uchun).

> DIQQAT: `auto`da qoldirmang — localning hozirgi versiyasida kanal o'lchash yo'q,
> `auto` = snapshot (xavfsiz tomon). Kanal o'lchash qo'shilgach `auto` videoga ham
> o'ta oladi. `low/medium/high` — hozircha uchchalasi ham kamera SUB-oqimini
> transkodlashsiz uzatadi (bitrate'ni kamera SUB sozlamasi belgilaydi).

## 8. Tekshirish (≤60 soniya ichida)

1. `docker logs karier-mediamtx --tail 20` — `is publishing to path 'karyer_...'` qatori chiqadi (agent ulandi)
2. web-quarry → Live: pleer (HLS) ochiladi, `live_mode: "hls"`
3. Kechikish 2-6s — normal
4. Agent uzilsa 10s ichida yo'l yopiladi (readTimeout) — "qotgan" oqim qolmaydi

## Muammo bo'lsa

- **Pleer ochilmadi, hali ham rasm:** backend qayta ishga tushirilganmi (env o'qildimi)? `GET /api/agent/config` (agent tokeni bilan) → `live_stream.push_url` endi `rtsp://agent:***@...` bo'lishi kerak (None emas).
- **MediaMTX'da publish ko'rinmayapti:** 8554 firewall'da ochiqmi; parollar (yml ↔ env) bir xilmi.
- **Publish bor, pleer qora:** nginx location'lar to'g'rimi (`/live/hls/<yo'l>/index.m3u8` → 8888).
- **Kamera 2-SUB ulanishni rad etsa** (localda detektor SUB'ni ushlab turadi, ffmpeg ikkinchi bo'lib ulanadi — Dahua odatda 2-3 taga ruxsat beradi): kamera web-interfeysida substream ulanish limiti; yechim bo'lmasa local'da detektorni main'ga o'tkazish mumkin (menga ayting).

## Eslatmalar (oldingi ro'yxatdan, hali ochiq)

  bo'lib `_camera_id_` bo'lyapti — template ishlamaydi (localda workaround bor,
  lekin serverda tuzatilgani to'g'ri: kod va kamerani alohida tozalash).

  640×480 @ 512-768 kbps ga qo'yish tavsiya etiladi (video shu tezlikda oqadi).
